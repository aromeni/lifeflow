# Stage 11A Phase 6A.1 — Visual Baseline Corrections

**Date:** 2026-08-05

Two of the repository's existing macOS (`-darwin`) visual-regression baselines under `apps/web/e2e-design/visual-regression.spec.ts-snapshots/` changed as a direct, intended consequence of this phase's fix, not as incidental drift:

- **`landing-darwin.png`** previously showed a live, clickable "Sign in with Google" button. This was captured against a local development environment with real Google client configuration left in place from an earlier phase (`GOOGLE_OAUTH_ENABLED=true`) but both Phase 6A per-flow flags at their safe `false` default — exactly the discrepancy this phase fixes (see `existing-frontend-behaviour.md`). Confirmed by running the *unmodified* pre-Phase-6A.1 code against the same environment: the old baseline was reproduced exactly. After this phase's fix, the same environment correctly shows the "Google sign-in is not enabled in this environment (development only)." text instead. The corresponding CI (`linux`) baseline, `landing-linux.png`, already showed the correct disabled state (CI's environment has no leftover Google client configuration at all) and required no change — independent confirmation that the fix produces the same, already-correct rendering CI has had all along.
- **`connections-darwin.png`** previously showed a live "Connect Google" link even with no Google integration authorised. After this phase's fix it shows "Connecting a Google account is not enabled in this environment." instead, changing the card's rendered height. The corresponding `connections-linux.png` CI baseline needed the equivalent update, since CI's environment has never had connector consent authorised either. This could not be generated locally without a real Linux/Chromium environment — a local ad-hoc Linux container attempt surfaced a fontconfig generic-sans-serif misconfiguration specific to that container (resolving to a CJK fallback font), which was fixed for a same-container sanity check but not trusted as the source of a committed baseline. Instead, the repository's own established precedent for this exact situation (commits `f0ba155`/`21d0420`, Stage 11A Phase 1's F-002 closure) was followed: a temporary, branch-scoped GitHub Actions workflow (`_tmp-regen-linux-baselines.yml`) ran `scripts/e2e-design.sh visual-regression.spec.ts --update-snapshots` on real `ubuntu-latest` CI and uploaded the regenerated `*-linux.png` files as an artifact. All eight downloaded baselines were compared byte-for-byte against what was already committed: seven were identical (confirming this PR has no other visual effect on CI's environment), and only `connections-linux.png` differed — that one file was committed and the temporary workflow removed in the same commit.

Neither change reflects a change in visual design intent — both are the direct, correct consequence of no longer showing a control that would predictably fail immediately after being clicked.
