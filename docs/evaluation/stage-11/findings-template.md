# Stage 11 — Findings Report Template

**Status:** Planning document, to be filled in after evaluation rounds run · **Date:** 2026-07-30

Companion: [success-criteria.md](success-criteria.md) · [product-hypotheses.md](product-hypotheses.md) · [issue-register-template.md](issue-register-template.md) · [go-no-go-template.md](go-no-go-template.md)

**This template must not be filled in until participant sessions have actually run.** No session has run as of this planning gate.

## 1. Summary

One paragraph: what was tested, how many participants in each round, headline result.

## 2. Participant profile achieved vs. target

Table comparing [stage-11-plan.md](../../delivery/stage-11-plan.md) §2's target profile against who actually participated; note any deviation and its implication for how the results should be read.

## 3. Task-success rates

Per task (T1–T20): success / partial / failure counts, per round.

## 4. Median task times

Per task, per round.

## 5. Assistance frequency

Per task, per round: % requiring minimal / substantial / facilitator-completed help.

## 6. Safety-comprehension rates

Per safety-questionnaire item, per round, with explicit call-out of any critical-item failure.

## 7. Relevance, usefulness, trust ratings

From [post-session-questionnaire.md](post-session-questionnaire.md), per round, with averages and spread (not just the mean).

## 8. SUS (or equivalent) score

Per round, with the standard SUS interpretation band noted (e.g., "above average" / "below average") without overstating precision given the sample size.

## 9. Recurring qualitative themes

Grouped by theme, with participant-ID citations (not names) and representative anonymised quotes.

## 10. Issue counts by severity

Pulled from [issue-register-template.md](issue-register-template.md): count of P0/P1/P2/P3, with resolution status for each.

## 11. Round 1 vs. Round 2 comparison

For every metric that appears in both rounds: did it improve, and by how much? Call out any metric that did not improve despite a Round 1 fix.

## 12. Threshold pass/fail table

One row per [success-criteria.md](success-criteria.md) metric: measured value, threshold, pass/fail.

## 13. Minority and outlier observations

Anything only one participant raised, but that constitutes a plausible safety or trust concern, is recorded here even if it doesn't move an aggregate number.

## 14. Limitations

Explicitly state: sample sizes (3–8 and 5–8) are too small for statistical generalisation; all findings are descriptive; synthetic-data-only sessions may not surface issues that only appear with real, messier inbox content; single-facilitator sessions carry facilitator-consistency risk.

## 15. Evidence for/against each product hypothesis

One row per hypothesis in [product-hypotheses.md](product-hypotheses.md): supported / partially supported / not supported / inconclusive, with the evidence cited.

## 16. Data-handling confirmation

Confirmation that evaluation working data has been (or will be) deleted per [data-governance.md](data-governance.md)'s retention period, and the date this occurred or is scheduled.

## 17. Recommendation feeding the go/no-go decision

Does not itself decide GO/CONDITIONAL GO/NO-GO — that decision and its explicit criteria live in [go-no-go-template.md](go-no-go-template.md). This section states what this report's evidence supports.
